# CLAUDE.md — памятка для Claude Code по проекту «Включайся!»

Этот файл читает Claude Code при открытии репозитория. Владелец проекта
(Кирилл) сам не писал код и не знает его устройства — **объясняй простым
языком, по-русски, без жаргона**, и сначала диагностируй, потом чини.

## Что это

Автоматизация утренней графики телепередачи «Включайся!» в **After Effects**
(только AE, не Premiere): панель-расширение (CEP) + проект-шаблон + установщик
Windows. Кнопка в панели подтягивает погоду, курс валют, дату, именины,
новости и гороскоп и расставляет переходы. Подробности и таблица функций —
в `README.md`. Тут только то, чего в README нет.

Репозиторий публичный: `keriklamar/vklyuchaysya-ae`. Пользователи (коллеги)
ставят готовый `Vklyuchaysya_Setup.exe` из **Releases**; код они не трогают.

## Карта файлов (что где менять)

| Что нужно | Файл |
|---|---|
| Кнопки, вёрстка панели | `panel/AutoPogodaPanel/client/index.html`, `style.css` |
| Логика интерфейса, сеть, чтение .docx, гороскоп, «Скачать» | `panel/AutoPogodaPanel/client/js/main.js` |
| Всё, что пишет в проект AE (слои, композиции, переходы) | `panel/AutoPogodaPanel/host/host.jsx` — **ExtendScript = ES3**: без `let/const`, стрелочных функций, `JSON` и т.п. |
| Версии AE, на которых панель грузится | `panel/AutoPogodaPanel/CSXS/manifest.xml` (сейчас `AEFT [24.0,99.9]`, CSXS 9.0) |
| Установщик | `installer/vklyuchaysya.iss` (Inno Setup 6), текст для пользователя — `installer/README.txt` |
| Проекты AE | `project/` — два файла: `подложка утро_0.3.aep` (AE **2026**) и `подложка утро_0.3 (AE 2024+).aep` (AE 2024/2025). Старшая версия AE младшую не открывает |
| Диагностика | `tools/diagnose.ps1`, `tools/diagnose.bat` (см. ниже) |

Имена композиций и слоёв в `.aep` **регистрозависимы**, `host.jsx` ищет их по
имени (`ОСНОВА`, `ОСНОВА без др` и др.). Переименовал в проекте — сломал панель
(симптом: `ERROR: comp not found` / `layer not found`).

## Как устроена установка (и почему ломается)

Панель грузится в AE, только если выполнены ВСЕ условия, и всё это — **в профиле
того Windows-пользователя, под которым работает AE**:

1. Папка панели: `%APPDATA%\Adobe\CEP\extensions\AutoPogodaPanel` (внутри `CSXS\manifest.xml`).
2. Реестр `HKCU\Software\Adobe\CSXS.9…12`, строка `PlayerDebugMode = "1"`
   (без неё AE не грузит неподписанные панели). CSXS.12 — это AE 2025/2026.
3. В AE включена галочка *Edit → Preferences → Scripting & Expressions →
   Allow Scripts to Write Files and Access Network* (дальше — перезапуск AE).
4. AE перезапущена после установки. Пункт меню: `Window → Extensions → Включайся!`.

## Журнал проблем и решений

- **Панели нет в Window → Extensions (2026-11-04, новый компьютер, AE 2025).**
  Диагностика показала: ключа `PlayerDebugMode` в `CSXS.12` нет и папки панели
  в профиле пользователя нет. Версия AE ни при чём (25 входит в манифест).
  Причина, вероятнее всего: установщик запускали «от имени администратора»
  (под другой учётной записью) → `{userappdata}` и `HKCU` указывали на профиль
  админа. Руками исправили: записали ключ `CSXS.9–12` и скопировали
  `panel/AutoPogodaPanel` в `%APPDATA%\Adobe\CEP\extensions\`.
  **Исправление в коде:** в `installer/vklyuchaysya.iss` убрано
  `PrivilegesRequiredOverridesAllowed=dialog`, добавлены блокировка запуска с
  повышенными правами (`InitializeSetup`) и проверка результата после установки
  (`PanelInstalledOk`), версия 1.1.9.
- **Проект «не открывается» в AE 2024/2025.** Основной `.aep` сохранён в AE 2026.
  Нужно открывать `подложка утро_0.3 (AE 2024+).aep`. Добавлено в
  `installer/README.txt`.
- **Релиз 1.1.8 (2026-09-29) старше кнопки «Скачать гороскоп»** (добавлена
  коммитом `4371f33`, 2026-10-08). У пользователей, ставивших 1.1.8, кнопки нет —
  нужен новый релиз.
- **Гороскоп:** кнопка «Сгенерировать гороскоп» берёт 12 знаков (заглавными) +
  случайные фразы без повторов из `гороскоп.txt` (лежит рядом с папкой `Graph`,
  его находит `getProjectFolder()` в `host.jsx`). «Скачать гороскоп» сейчас
  открывает окно сохранения и пишет `.docx` или `.txt` (txt с BOM, чтобы Блокнот
  читал кириллицу). По просьбе владельца авто-скачивание в «Загрузки» **не
  делали** — кнопка уже есть, её просто не было в старом релизе.

## Как диагностировать проблему у пользователя (делай ТАК)

Не проси пользователя вводить команды по одной. Есть скрипт, который только
читает систему и ничего не меняет (профиль, права, папка панели, реестр,
CSXS.8–13, галочка скриптов в AE, шрифты, проект, сеть, Defender, логи CEP):

- Пользователь запускает **двойным кликом `diagnose.bat`** (он лежит в папке
  установки, рядом с README), либо одной строкой в PowerShell (без админа):

  ```
  powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/keriklamar/vklyuchaysya-ae/main/tools/diagnose.ps1 | iex"
  ```

- Отчёт печатается, сохраняется на рабочий стол (`vklyuchaysya_diagnose.txt`) и
  копируется в буфер — его вставляют в Telegram. Ты читаешь отчёт и ищешь:
  `elevated = True`, `MISSING` у файлов панели, `PlayerDebugMode MISSING`,
  панель «FOUND in <другой профиль>», `pref not found` (галочка скриптов),
  `FAIL` у сети, находки Defender.

Если для новой проблемы в отчёте не хватает данных — **дополни
`tools/diagnose.ps1`**, а не проси пользователя вручную (файл только латиницей —
иначе ломается кодировка при запуске через `irm | iex` на PowerShell 5.1).

## Правила работы с репозиторием

- Не пушить в `main` и не публиковать релиз без прямой просьбы владельца;
  работай в ветке, открывай PR.
- Установщик собирается на Windows:
  `"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer\vklyuchaysya.iss` →
  `installer\Output\Vklyuchaysya_Setup.exe`. Готовый exe — ассет GitHub Release.
  Версия задаётся `#define AppVersion` в `.iss`.
- В `host.jsx` секретов нет; ключ `KALENDARIK_API_KEY` публичный (ограничен по
  Referer). Не добавляй в репозиторий пароли/токены.
- После правок кода панели проверять можно только в живой AE; если проверить не
  удалось — так и скажи владельцу, не заявляй «работает».
